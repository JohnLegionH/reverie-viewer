# Sculpt parity fixtures (the test strategy, section 3.2)

**Status: a documented REFERENCE, no longer the oracle.** The viewer draws sculpts with the
official viewer's sampler (Docs/SCULPT-SAMPLER-SPEC.md); these fixtures still verify the kept port
(`SculptMesher.BuildReference`), and `SculptMesherTests.How_the_official_sampler_differs_from_the_web_viewer_reference`
records where the two agree (3 of 207 cases identical, all planes).

Originally one oracle, two implementations: the web viewer's TypeScript sculpt mesher (`client/src/mesh/sculpt.ts`) and this
repo's C# port (`core/Viewer.Core/Meshing/SculptMesher.cs`). The web viewer has no sculpt fixtures of its own, so the
oracle is its complete output, dumped the way PrimMesher's was (fixtures/primmesher).

## `web-viewer-oracle.json.gz`

- Source: web-viewer `master` at `bb91ba5`, file `client/src/mesh/sculpt.ts` (last changed `5d66b43`), read with
  `git show` (the web-viewer tree is read-only).
- Generated by `generate/dump.mjs`, run in a scratch folder with an existing
  Node 22.16 (`node --experimental-strip-types dump.mjs <out>`), next to the exported `sculpt.ts`, with
  `generate/three-stub.js` as `node_modules/three/index.js` (the two three.js classes the file touches) and an
  `ImageData` stand-in. Nothing was installed and nothing was written into the web-viewer tree.
- Content: 9 generated maps (sphere, torus, plane, cylinder at 64x64; sphere 128x64 and 256x256; noise 32x16, 7x5
  and 2x2), stored as base64 RGB so both sides read the same bytes; 208 cases of `buildSculptGeometry(map, type,
  mirror, invert, lod)` over types 1-4, the four mirror/invert combinations and lod 6/8/16/32 (the official viewer's
  side counts) plus 64 (the web viewer's fixed value): positions, normals and UVs rounded to 1e-6, indices exact.
- The C# test compares indices exactly, positions and UVs to 2e-6, normals to 2e-5.
- Redistribution: generated geometry from BSD-licensed code (see THIRD-PARTY-NOTICES.md) over synthetic maps; no
  grid content.
